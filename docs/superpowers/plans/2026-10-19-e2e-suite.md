> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close #18. Every flow in spec §14.3 gets an E2E test that checks the whole flow through what the user can see, and the tests pass in CI.

**Architecture:** The harness (spec §14.2) and most flows already exist. #11–#15 each added their own flows to `Tests/E2E/`, and CI's `e2e` job runs all 22 tests. This plan does three things. ## Global Constraints

- **E2E tests drive the app only through user input and check only what the user can observe** (spec §14.1, `CONTRIBUTING.md`): the window, the fake server's messages, files on disk. The log and `app.toml` are files on disk, so tests may read them, but a flow whose result shows in the window checks the window.
- **The runner is sandboxed with read-only access to the disk** (#18's comments): no test writes a file. Files to open come from `Tests/Fixtures/` via `E2EApp.fixture(_:)`. Files to save go to `E2EApp.savedFile(_:)`.
- **Mouse drags use `click(forDuration:thenDragTo:)`, and coordinates are built from `.zero` plus explicit offsets** (#57, #71). Keep the comments that say so.
- **`relaunch()` kills the app without letting it save**, so before calling it, wait for what must be saved with `settingsText(containing:)`.
- **A picture comparison means something only while the window is still.** Compare pictures only while the timer isn't running. Before relying on "the picture changed", first check that two pictures taken in a row are equal.
- **No app code changes.** If a test shows an app bug, fix it in this pull request with a test at the lowest level that catches it (`CONTRIBUTING.md`), and say so in the PR.
- **Out of scope, with their own issues:** #75 (resize test short locally), #81 (right-click menu items missing in a full local run), #85 (screenshots failing locally). All three pass in CI today. If one fails this branch's CI, stop and report it rather than retrying until it passes.
- **No user-visible change**, so no wiki update and no screenshots to retake. Say so in the PR.

## Review Focus

- **A test that passes whatever the app does.** Each "the picture changed" check in Task 3 has the "two pictures in a row are equal" check in front of it.
- **Pixel equality across a relaunch** (Task 3) fails if the window opens at another size or on another display's scale. The test checks the frame first, so a failure names the real cause.
- **The fake server's message order** (Task 5): every command's event comes before its reply. Assert on exact indices, not "some message matches", because the server's own split already sent a `Splitted`.
- **A one-segment run finishes on its first split.** Task 4 relies on that (the default run). Task 5 must not use it, because the local split must still reach a running timer, so it opens `GameTime.lss` (13 segments).
- **Helpers moved in Task 1 must keep their timeouts and failure messages**, or a later flake becomes harder to read than it is today.

### Task 3: Pictures that can fail: Compare Against, timing method, relaunch

- [ ] **Step 1: Write the new Compare Against test.** It doesn't start the timer. The default layout's splits show each segment's comparison time, which differs between Personal Best and Best Segments, and between Real Time and Game Time in `GameTime.lss`.

```swift
@MainActor
func testCompareAgainstAndTheTimingMethodChangeWhatTheWindowShows() {
    let e2e = E2EApp.launched(picks: ["GameTime.lss"])
    e2e.choose("timer-open-splits-choose", under: ["timer-open-splits"])
    e2e.waitForLog("Opened splits")
    let window = e2e.timerWindow
    let opened = e2e.picture(of: window)
    XCTAssertEqual(e2e.picture(of: window), opened, "the window changes by itself")

    e2e.choose("Best Segments", under: ["timer-compare-against"])
    let bestSegments = e2e.waitForPicture(differentFrom: opened, in: window)
    XCTAssertNotEqual(bestSegments, opened, "Best Segments didn't change the window")

    e2e.choose("Game Time", under: ["timer-compare-against"])
    XCTAssertNotEqual(
        e2e.waitForPicture(differentFrom: bestSegments, in: window), bestSegments,
        "Game Time didn't change the window")
}
```

`"Opened splits"` is `FileController`'s log line (`App/Files/FileController.swift`). Delete `MenuTests.testCompareAgainstAndTheTimingMethod` and `FileTests.testCompareAgainstChangesWhatTheWindowShows`: this test covers both, through the window.

After `relaunch()` and the frame checks, wait for the reopened files: `waitForPicture(differentFrom: defaultPicture, in: window)` (the first picture after launch may be the default layout). Then `XCTAssertEqual(e2e.picture(of: window), shown, "the relaunch didn't reopen the splits and layout")`. Remove the `after` check that reads `app.toml`. It only read the file the test had already checked before the relaunch.
