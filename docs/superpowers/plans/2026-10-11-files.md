# Files Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open and save splits, open layouts and save them as `.ls1l`, keep recent files, ask before losing unsaved splits, ask what a reset with new best times does, follow the layout a run links to, and reopen the last splits and layout at launch (spec §6, §7, §7.1) (issue #12).

**Architecture:** `SplitsFile` and `LayoutFile` (`App/Files/`) turn files into livesplit-core's `Run` and `Layout` and back, with errors the user can read (`FileLoadError`). `TimerContent` gets a replaceable run and layout, and answers whether the run has unsaved changes. `TimerWindowController.showLayout(_:path:)` switches the window to another layout and its saved frame. `FilePicker` is the one way the app asks for a file: `SystemFilePicker` shows `NSOpenPanel` and `NSSavePanel`, and `ScriptedFilePicker` answers from the `-LSOPickedFiles` launch argument in Debug builds (spec §14.2). `FileAlerts` shows the save, load-error and save-error alerts. `FileController` runs every Files command and records paths in `app.toml`; `TimerMenus` adds its items to both menus. `CommandRunner` asks the *Yes / No / Don't Reset* question on the main thread while its queue waits, saves the answer, and drops the commands that waited behind it.

**Tech Stack:** Swift 6, AppKit (`NSOpenPanel`, `NSSavePanel`, `NSAlert`, `NSMenu`), UniformTypeIdentifiers, livesplit-core's C API (`Run_parse`, `Run_save_as_lss`, `Layout_parse_json`, `Layout_parse_original_livesplit`, `Layout_settings_as_json`, `Timer_set_run`, `Timer_mark_as_unmodified`, `Run_has_been_modified`, `Run_linked_layout`), Swift Testing, XCUITest, XcodeGen.

## Global Constraints

- Swift never reimplements timer rules (spec §4). Timer commands, including the reset before quitting, go through `CommandRunner` and the event-reporting sink. Replacing the run (`Timer.setRun`) is not a timer command: it runs on the main thread under the write lock, only while no attempt is in progress.
- **No attempt is ever dropped by opening or closing splits.** Open Splits, its recent files and Close Splits are enabled only while the timer's phase is `notRunning` (spec §7). `Timer.setRun` resets with `update_splits = false`, so an ended attempt that wasn't reset would lose its times.
- `EventSink`'s callback rules still hold (its doc comments). `decideReset` runs on the command's thread and may wait for the main thread; the main thread never waits for the command queue. Nothing on the main thread takes the timer's write lock while it could be waiting on the reset question: `TimerContent.setRun` runs only from menu actions, which a modal alert blocks.
- **`app.toml` paths** are `url.standardizedFileURL.path`, so one file has one entry (#12, comment from #49). Opening or saving records `last_splits` / `last_layout` and adds to `recent_splits` / `recent_layouts` through `settings.update`. A file that fails to open changes nothing in `app.toml`.
- **Splits are always written as `.lss`** (`Run.saveAsLss()`), **layouts as `.ls1l`** (`Layout.settingsAsJson()`). Both writes are atomic and go to a symlink's target, as `SettingsStore.save()` does.
- **Saving marks the run unmodified only if it didn't change while being written:** read the text under the read lock, write it, then under the write lock call `markAsUnmodified()` only if `saveAsLss()` still returns the same text. A server command can change the run meanwhile (#14).
- **Error texts** (spec §7.1, §10, decided in #58): a file that can't be read gives macOS's reason (`error.localizedDescription`); a file that reads but doesn't parse gives `"<name>" isn't splits LiveSplit One for macOS can read.` or `"<name>" isn't a layout LiveSplit One for macOS can read.` A run with no segments counts as not splits, since a timer can't use it.
- **Linked layouts** (spec §7.1): after splits open from the menu, `LinkedLayout.path` opens that layout and a default link shows the default layout. A failure keeps the current layout and shows an overlay notice. No link: the layout doesn't change. At launch, `last_layout` wins and the link is ignored. The app never writes the link.
- **Item titles, exactly:** **Open Splits** (submenu: **Open…**, the recent files by file name, a separator, **Clear Menu**), **Save Splits** (⌘S), **Save Splits As…** (⇧⌘S), **Close Splits**, **Open Layout** (same submenu shape), **Save Layout As…**. The menu bar's new menu is **File**, between the app menu and **Control**.
- **Accessibility identifiers** on the right-click menu's items: `timer-open-splits`, `timer-open-splits-choose`, `timer-recent-splits-<index>` (0 is the most recent), `timer-clear-recent-splits`, `timer-save-splits`, `timer-save-splits-as`, `timer-close-splits`, `timer-open-layout`, `timer-open-layout-choose`, `timer-recent-layouts-<index>`, `timer-clear-recent-layouts`, `timer-save-layout-as`.
- **The reset question** (spec §7.1): message **Do you want to update your best times?**, informative text **This attempt has beaten some of your best times.**, buttons **Yes**, **No**, **Don't Reset**, in that order. *Yes* saves `reset_saves_best_times = true`, *No* saves `false`, *Don't Reset* saves nothing and answers `.cancel`.
- **The unsaved-changes alert:** message **Do you want to save the changes to "<name>"?** (or **…to your splits?** for a run with no file), informative text **Your changes will be lost if you don't save them.**, buttons **Save**, **Don't Save**, **Cancel**. Esc is Cancel.
- **Notices at launch:** `Couldn't reopen "<name>": <reason>`, where `<reason>` is `FileLoadError.reason`. For a linked layout: `Couldn't open the layout "<name>" these splits use: <reason>`.
- **Log lines** (spec §12.1), in `APP` (there is no files category; failures in `ERROR`): `Opened splits <path>`, `Opened layout <path>`, `Saved splits to <path>`, `Saved layout to <path>`, `Closed splits`, and in `ERROR` `Couldn't open <path>: <reason>` and `Couldn't save <path>: <reason>`; in `TIMER`, `<name> from <source> dropped: it waited behind the reset question`.
- `Shortcuts.reserved` gains `Meta+s` and `Shift+Meta+s` (⌘S, ⇧⌘S), and spec §7.3's list says so (comment from #56).

`App/Files/FileLoadError.swift`:

```swift
/// Why a splits or layout file didn't open (spec §7.1, §10). livesplit-core's parsers don't
/// say why a file didn't parse, so only macOS's reasons for not reading it are passed on.
enum FileLoadError: Error, Equatable, Sendable {
    /// macOS couldn't read the file: its reason, such as a missing file or no permission.
    case unreadable(String)
    case notSplits
    case notLayout

    /// The alert's text for the file named `file`.
    func message(file: String) -> String {
        switch self {
        case .unreadable(let reason): reason
        case .notSplits: "\"\(file)\" isn't splits LiveSplit One for macOS can read."
        case .notLayout: "\"\(file)\" isn't a layout LiveSplit One for macOS can read."
        }
    }

    /// The reason, for an overlay notice or the log, which name the file themselves.
    func reason(file: String) -> String {
        switch self {
        case .unreadable(let reason): reason
        case .notSplits: "it isn't splits this app can read"
        case .notLayout: "it isn't a layout this app can read"
        }
    }

    /// Reads `url`, turning macOS's error into `.unreadable`.
    static func read(_ url: URL) throws(FileLoadError) -> Data {
        do {
            return try Data(contentsOf: url)
        } catch {
            throw .unreadable(error.localizedDescription)
        }
    }
}
```

```swift
import Foundation
import LiveSplitCore

/// Splits files (spec §7.1): any format livesplit-core reads, always saved as `.lss`.
enum SplitsFile {
    /// The run in `url`, through livesplit-core's composite parser.
    static func load(_ url: URL) throws(FileLoadError) -> Run {
        let data = try FileLoadError.read(url)
        guard !data.isEmpty else { throw .notSplits }
        let result = data.withUnsafeBytes { bytes in
            // The path lets LiveSplit's relative image paths load.
            Run.parse(UnsafeMutableRawPointer(mutating: bytes.baseAddress), bytes.count, url.path)
        }
        guard result.parsedSuccessfully() else { throw .notSplits }
        let run = result.unwrap()
        // A timer can't use a run with no segments.
        guard run.len() > 0 else { throw .notSplits }
        return run
    }

    /// Whether Save Splits has to ask for a file name: the run has no file, or one that isn't
    /// `.lss`, which saving would overwrite in another format.
    static func needsNewName(_ path: String?) -> Bool {
        guard let path else { return true }
        return URL(filePath: path).pathExtension.lowercased() != "lss"
    }

    /// The name Save Splits As… suggests: the file's own name with `.lss`, or the game and
    /// category for a run with no file.
    static func suggestedName(path: String?, run: RunRef) -> String {
        if let path {
            return URL(filePath: path).deletingPathExtension().lastPathComponent + ".lss"
        }
        let name = run.extendedFileName(false)
        return (name.isEmpty ? "Splits" : name) + ".lss"
    }
}
```

```swift
import Foundation
import LiveSplitCore

/// Layout files (spec §7): `.ls1l` and `.lsl` open, and only `.ls1l` is written.
enum LayoutFile {
    /// The layout in `url`: LiveSplit One's JSON, else LiveSplit's XML, whatever the extension.
    static func load(_ url: URL) throws(FileLoadError) -> Layout {
        let data = try FileLoadError.read(url)
        guard !data.isEmpty else { throw .notLayout }
        if let text = String(data: data, encoding: .utf8), let layout = Layout.parseJson(text) {
            return layout
        }
        let layout = data.withUnsafeBytes { bytes in
            Layout.parseOriginalLivesplit(
                UnsafeMutableRawPointer(mutating: bytes.baseAddress), bytes.count)
        }
        guard let layout else { throw .notLayout }
        return layout
    }

    /// The name Save Layout As… suggests: the layout's own name with `.ls1l`, so an `.lsl` is
    /// never overwritten (spec §7).
    static func suggestedName(path: String?) -> String {
        guard let path else { return "Layout.ls1l" }
        return URL(filePath: path).deletingPathExtension().lastPathComponent + ".ls1l"
    }
}
```

```swift
enum TextFile {
```

```swift
    func setLayout(_ layout: Layout, keepingWindowSize: Bool) {

        dropNextSizeHint = keepingWindowSize

    @discardableResult
    func setRun(_ run: Run) -> Bool {

        timer.writeWith { rejected = $0.setRun(run) != nil }
        guard !rejected else { return false }
        imageCache.collect()
        markChanged()
        return true
    }

        timer.readWith { result = body($0.getRun()) }
        return result

        timer.readWith { phase = TimerPhase(rawValue: $0.currentPhase()) ?? .notRunning }
```

```swift
    /// Runs `body` on the main actor and waits for it on this thread, which is never the main
    /// thread: commands run on the command queue, and the server's on its own (#14).
    private static func waitOnMain<T: Sendable>(_ body: @escaping @MainActor @Sendable () -> T)
        -> T
    {
        precondition(!Thread.isMainThread)
        let result = Mutex<T?>(nil)
        let done = DispatchSemaphore(value: 0)
        Task { @MainActor in
            let value = body()
            result.withLock { $0 = value }
            done.signal()
        }
        done.wait()
        return result.withLock { $0! }
    }
```

`run(_:from:completion:)` captures `epoch.value` when it queues the command, and on the queue drops a command whose epoch is older:

```swift

        queue.async { [sink, log, changed, epoch] in
            guard epoch.value == queued else {
                log.record(
                    .timer, "\(name) from \(source.rawValue) dropped: it waited behind the "
                        + "reset question")
                completion?(nil)
                return
            }
            …
```

`completion` becomes `(@Sendable (String?) -> Void)?`; `nil` means dropped. `epoch` is a `Mutex<Int>` wrapper like `ResetPreference`. `AppDelegate`'s `remember` does `settings.update { $0.resetSavesBestTimes = value }` then `settingsChanged()`, so an open Settings window shows the new value next time it reloads.

- While it waits, other commands on the sink get `Busy` — but the menu's and keyboard's commands are behind it on the serial queue, so they never reach the sink until it returns; that's why they're dropped by epoch instead.
- `NSAlert.runModal()` inside a main-actor `Task` is fine: the run loop keeps running modally, so the timer still draws (drawing takes only the read lock, which the waiting reset doesn't hold).
